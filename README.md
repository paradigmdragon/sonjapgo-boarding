# 손잡고 탑승 시스템

**개발을 대기열이 아니라 흐름으로.**

사람과 AI의 코드 변경을 세이브하고, 충돌한 작업만 멈추며, 준비된 변경을 다음 배포로 연결하는 개발관제 시스템을 만듭니다.

> 현재는 **mock 데이터 기반 관제 UI 프로토타입**입니다. 실제 파일 감지·충돌 검사·GitHub 통합·배포·Sophia 연결은 구현되지 않았습니다. 체험 조작은 현재 탭에만 반영되며 새로고침하면 초기화됩니다.

계속 저장하고. 충돌할 때만 멈추고. 함께 만든 흔적은 남깁니다.

## 실행

Node.js 22 이상과 Python 3이 필요합니다. 외부 패키지 설치나 API 키는 필요하지 않습니다.

```sh
git clone https://github.com/paradigmdragon/sonjapgo-boarding.git
cd sonjapgo-boarding
npm run check
npm test
npm start
```

브라우저에서 http://127.0.0.1:4173 을 엽니다. ES 모듈을 사용하므로 HTML 파일을 직접 열지 않고 서버로 실행합니다.

## 현재 기능

- 작업 중·검표 중·탑승 가능·충돌·배포 대기 요약과 필터
- 시간순 세이브 스트림
- 크레딧 → 작업 → 변경 파일 → 검증 → 기여자 → GitHub 통합 → 배포 이력 상세
- 충돌 이유·영향·AI 제안 및 재검표·보류·순서 조정 체험
- 다음 배포편 탑승·취소
- 실험노선의 본선·실험 세이브 표시와 HOLD 체험
- 예시 크레딧·기여 역할

## 용어

| 용어 | 의미 |
| --- | --- |
| 승객 | 작업(Task) |
| 탑승권 | 수정 파일 |

| 크레딧 | 세이브포인트의 한 줄 제목 |
| 배포편 | 배포 묶음 |
| 실험노선 | Live Branch |

## 코드와 정본

- `dist/index.html`: 한국어 화면 골격
- `dist/style.css`: 반응형 스타일
- `dist/app.js`: 화면과 사용자 조작
- `dist/data.js`: mock 데이터 및 `MockRepository` 조회·조작 인터페이스
- `tests/`: mock 상태 규칙 확인

GitHub는 공개 협업 코드의 기준 저장소입니다. 지속 맥락·목적·작업 결과는 [손잡고 P70](https://sonjapgo.com/projects/70)에서 이어갑니다. GitHub 이슈·PR은 코드 협업에 사용하며 손잡고 Task 완료를 자동으로 뜻하지 않습니다.

[현재 Sites 체험판](https://sonjapgo-boarding-control.paradigmdragon.chatgpt.site)은 소유자 전용입니다. GitHub 저장소 공개와 Sites 접근 권한은 별개입니다.

## Sites와의 관계

현재 Sites v1은 별도 배포 저장소의 소스 `6dbd26e44f925ca6e882efb4af22c70b9267378f`에서 게시됐습니다. 이 저장소의 최초 MVP 파일은 그 코드에서 가져왔습니다.

이 저장소에 push해도 Sites가 자동 배포되지는 않습니다. 제품 변경은 이 저장소에서 검토하고, 승인된 버전의 `dist/`를 기존 Sites 배포 경로에 반영합니다. `.openai/hosting.json`과 배포 자격증명은 공개 저장소에 포함하지 않습니다. 별도 배포 저장소에서 제품 코드를 독립적으로 수정하지 않습니다.

## 다음 검증 목표

작은 저장소 하나에서 실제 변경 → 세이브 → 검표 근거 → 충돌 작업만 보류 → 통합 결과 기록을 확인합니다. 기존 손잡고·GitHub·Sophia 계약을 먼저 재사용하며 새 DB나 큐를 전제로 하지 않습니다.

알려진 제약:

- 탑승은 mock 배포편 예약이며 GitHub 통합 완료를 보장하지 않습니다.
- 검표는 실제 검사 실행이 아닙니다. 파일 중복 여부만으로 의미·계약 충돌을 판정할 수 없습니다.
- 실험노선은 고정 예시이며 실제 rebase·overlay·본선 추적 기능이 없습니다.
- S-1850은 충돌 설명용 참조이며 상세 객체가 없습니다.
- 메뉴 전환 시 스크롤 위치, 긴 주체명, 상세 조작 후 펼침 상태에 UX 개선이 필요합니다.
- 외부 데이터 연결 전 HTML 문자열 삽입을 안전한 텍스트 출력으로 바꿔야 합니다.
- 모바일·확대 화면·실제 연동 E2E는 추가 검증이 필요합니다.
